页面图标选择器 · 三款原型对比

对应 UC-17：全量 emoji（本样例只渲染子集）+ 图片图标。三款共享真实状态：任一款里的选择、搜索词、上传与最近使用会同步到另外两款。点击即选中；真实界面里选中后弹层关闭。

方案 A · 单栏延展 推荐借自 Notion 自己的图标弹层

改动面最小：保持现有 340px 弹层与 chrome 不动，内容改为「最近使用」行 + 全量分组 + 顶部图片磁贴。换掉的结构：手维护的 3 组 72 个 → 数据驱动的标准类目。代价：上下滑动浏览、图片入口与 emoji 混排。适合保持熟悉感的默认方向。

📄点击页面图标弹出

「最近使用」行需新增 localStorage 机制（尚未存在），跨设备不同步；删掉该行即为纯清单方案。图片磁贴固定在第一格，关键词命中「图片 / upload / image」时同样可见。

方案 B · 左栏目录 + 右栏网格 借自 macOS 字符检视器

浏览最快：左栏列出全部类目（含「最近」与「上传图片」），右栏只渲染当前类目。搜索默认限定在选中类目；选「全部」时全局搜索。换掉的结构：单栏滚动 → 双栏导航。代价：新增 rail chrome 与选中态，弹层信息密度上升，窄屏需收编。

📄点击页面图标弹出

左栏「最近」与 A 的最近行共用同一份状态；「上传图片」项点亮时右栏变为上传区。类目图标用该组第一个 emoji 充当，不引入第二套图标。

方案 C · Emoji / Upload 页签 借自现有封面的 Gallery / Upload 页签

结构最克制：沿用产品里已有的页签 chrome，把「Emoji」与「Upload」完全分开。Emoji 页内加一行类目胶囊做快速跳转（锚点滚动，不改 chrome）。换掉的结构：单流清单 → 分页 + 内部锚点。代价：emoji 与图片被页签隔开，一步变两步；搜索框随页签换语境。

📄点击页面图标弹出

「Upload」选中时搜索框隐藏（占位仍留，避免高度跳动）；类目胶囊只做滚动锚点，搜索仍是全量。上传后可从最近行回到图片图标。

留给 UC / 实施的待定项

  • 「最近使用」是否纳入本轮：需 localStorage，三款都可去掉该行而不影响结构。
  • emoji 数据包选型（emojibase-data 优先，含中文标注）；清单不做白名单。
  • 图片图标上传后是否生成 preview 缩略图（沿用 cover 的 preview 字段）。
  • 选择后弹层即关闭（现状）；本原型为对比需要保持打开。
  • 三款均未验证真实 emoji 全量渲染性能：虚拟滚动按需要在实施时评估。
