# Agent 提案审核界面

状态：本轮实现与验收完成，2026-11-04 归档。本文保留当轮方案与结果。当前系统说明见 [Atlas](../../atlas/README.md)。

日期：2026-11-04。

## 意图与范围

用户要求改善刚展示的界面。本次优化 UC-06 的提案审核。保留 Notes 的暖灰、白纸、蓝色动作及现有字体。用户先判断修改，再应用或拒绝。

## 设计选择

比较了原文与改后并列、行内修订两种结构。采用行内修订。短文字不再重复两段，手机也无需切换列。

- 同段文字操作按原顺序生成一份对照。
- 删除使用删除线，新增使用下划线和浅底。颜色不是唯一标记。
- 作者、时间与修改范围组成一行。待处理状态由筛选表达。
- 未修改的长上下文可收起。所有改动仍保留，并可展开完整段落。
- 按钮紧跟所属提案。一次仅审核一条提案。
- 格式、结构及历史提案保留操作明细。它们不显示推测的原文。

## 数据边界

只有本地页面代次及完整修订与提案基础相同，才生成文字对照。正文变化后显示失效提示，并停用应用按钮。服务端仍执行最终权限与修订检查。

预览仅处理文本，不修改页面。使用现有 diff 依赖生成标记。弹窗关闭时不计算页面修订。逐段差异按输入字符串缓存。

## 交互与验证

复用 Modal 入场与返回焦点。筛选底板移动。按钮按下即时反馈，提交中显示进度。减少动态设置关闭这些动效。

生产构建通过。核心 25/25 与 HTTP 34/34 通过。真实审核的两个用例各连续执行三次，6/6 通过。它们核对替换标记、长文展开与收起、双端正文、应用、拒绝及失效提案。原生 Enter、Escape 和返回焦点另有三轮通过记录。
