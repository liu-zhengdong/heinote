管理台「备份」页签：站点数据自动备份到云盘

UC-31 的三方向原型。同一数据、同一组任务：看上次备份结果、配 WebDAV、改计划、手动触发、应对失败。差异在「备份这件事在管理台里是什么」：A 把它当成需要巡检的状态对象，B 把它当成一个行式能力对象，C 把每次归档当成一等对象。

推荐方向 B：备份是低频巡检任务，进页签的第一眼要回答「上次成没成」；B 的状态行直接给答案，配置与操作是同一平面的同构行，与管理台既有行式语言一致，新范式为零。A 的状态瓦片更像站点概览，把低频任务做成了仪表盘；C 的归档检查器对「恢复由 Agent 操作」是过剩的对象化——归档明细 Agent 查 API 就行，管理员不需要逐片检查。

方向 A · 状态面板 + 处理队列借审美 031 的概览：度量瓦片给规模感，「需要处理」行给行动入口；配置收在底部。
方向 B · 行式对象借审美 030 的行式对象：状态、目标、计划、操作全是同构行，一个平面装完。
方向 C · 清单 + 检查器借审美 031 的主从：左列「自动备份」+ 最近归档，右栏检查器显示所选对象的配置或分片明细。
