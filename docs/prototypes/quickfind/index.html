⌘K 快速查找：命中要看得见，行要能喘气

同一个弹层、同一份数据、同一条查询。顶栏 Tab 在「现状」与三个方向之间切换：范围机制分别是输入行段控 / 底栏命令条 / 末尾动作；行距统一放宽、摘要升 12.5px；命中标记用右侧三档开关整体对比（现状页不受开关影响，保持线上长相）。

推荐：方向 A + 命中浅底块。范围二选一本来就是段控的形状，放进输入行后弹层回到输入 + 列表两段；命中标记里「加粗」没有信息量、「蓝字」与链接色混淆，浅底块是中文全文搜索的常见记号（浏览器页内查找同款心智），一眼定位命中位置，且不占颜色语义——蓝留给动作。

命中标记
现状 · 范围独占一行线上长相：输入行下方一整行「搜索范围 + 原生 select」，行距紧凑，命中仅加粗，文案中英混排。
方向 A · 范围段收进输入行输入行右侧一段双选「当前空间 / 所有空间」，范围与查询同层，不占结果区；行保留现单行形态。
范围仍是控件、随时可见可改；代价是输入行在窄屏略挤（本例 520px 宽余量充足）。
方向 B · 底栏命令条借 Spotlight 的底条：左下是范围入口（上弹小菜单），右下是键位提示；结果行改两行，面包屑与摘要同属元信息行。
弹层有了「头中脚」的完整骨架，以后加动词不用再加行；代价是底条对当前只有两个选项的范围是重量级范式。
方向 C · 范围是末尾动作借 Notion 搜索筛选的行内 token：默认只查当前空间，不显示任何控件；结果末尾一行「在全部空间中搜索」展开范围，展开后范围变成输入框里的可移除 token。
默认状态最干净——范围不存在，只有一条路；代价是「所有空间」藏得最深，且 token 语义需要用户学过这个范式。
