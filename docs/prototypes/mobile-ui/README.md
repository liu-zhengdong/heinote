## 问题与基线

当前代码在视口窄于 `560px`（`src/hooks/useFold.ts` 的 `FOLD = 560`）时仍沿用桌面小窗逻辑：左侧常驻 `46px` rail、顶栏面包屑与操作钮挤在一起、侧栏抽屉仅 `232px` 宽、Database 行详情侧栏盖在 `344px` 区域上、编辑时缺少随软键盘贴边的块操作与格式工具条，也未考虑刘海屏与底部手势条安全区（`safe-area-inset-*`）。

## 对比方案

打开 `index.html` 后可在顶栏水平切换 **现状** 与三个结构不同的候选方向（各方向状态独立、互不联动，默认浅色主题，支持右上角切换深色）：

- **现状对照**：复现 `46px` 常驻窄轨 + `232px` 抽屉 + 无工具条软键盘 + 桌面风格 `SidePeek` 的真实拥挤度。
- **方向 A · 顶栏侧滑抽屉**（借自 Bear / 苹果备忘录 / 审美 033）：去掉常驻底栏，阅读区最大；顶栏单行（`☰` + 标题 + 搜索 + `···`），向下滚动自动上收；左侧 `84%` 宽全高抽屉支持横滑手势收起；页面菜单、快速查找与行详情采用圆角 Bottom Sheet。
- **方向 B · 底部 Tab 推进栈**（借自 Notion Mobile / iOS 原生推进栈）：底部常驻四格 Tab 栏（目录 / 搜索 / 新建 / 收藏），子页与行详情走 iOS 全屏推进栈（`< 返回`）；进入编辑态时自动收起 Tab 栏让位给贴键盘工具条，避免与底部栏叠罗汉。
- **方向 C · 底部悬浮命令坞（推荐）**：顶部采用无边框安静「纸眉」；高频三动作（`☰ 目录` · `🔍 搜索或跳转…` · `+ 新建`）收进底部居中的悬浮胶囊命令坞，下滑沉浸阅读时自动收拢到右下角；目录从底部 78% Sheet 拉起，彻底避开 iOS / Android 左边缘系统返回手势冲突；编辑态命令坞平滑让位给贴键盘工具条；Database 行详情支持 `68% / 94%` 两段式 Sheet；公开分享页底部悬停 `[☰ 目录 · 研发手册]` 胶囊。

## 正式实现时的 Web 平台要点

原型工作台内为了把抽屉和弹层留在 `390×844` 手机画框里，使用了作用域内的绝对定位容器；真正落回 `src/` 时按以下标准实现：

- **可横滑抽屉（方向 A 若入选）**：采用 `popover="manual"` + `scroll-snap-type: x mandatory` + `overscroll-behavior: none`，抽屉高度使用 `100svh` 避免 iOS Safari 地址栏伸缩导致抽屉跳动，并配合 `@supports (animation-timeline: scroll())` 做遮罩渐隐。
- **动态视口与软键盘**：外层工作区使用 `100dvh`，文档内宽表格与代码块置于带 `role="region" tabindex="0"` 的局部横向滚动容器中，不在 `html`/`body` 上写 `overflow-x: hidden`；编辑工具条基于 `window.visualViewport` 贴合软键盘上沿。
- **安全区与触控热区**：固定顶/底栏采用 `env(safe-area-inset-*)`，滚动容器配 `scroll-padding-top` / `scroll-padding-bottom` 避免焦点元素被遮挡；所有触控目标保持 `≥ 44×44px` 点击区（紧凑图标用 `::after` 扩展命中面积）。
- **容器响应**：业务组件内部优先通过 `@container` 查询适配窄屏卡片与表格，而非散落视口媒体查询。
