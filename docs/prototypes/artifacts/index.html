内嵌 Artifact：三种展示方向

同一个 demo「小订单追踪器」放进三种壳。壳不同，应用本身不变——比的是固定入口、占面大小和嵌入关系。点进去直接操作。

方向 A · 借自 Notion embed
笔记内嵌块
应用作为一行块躺在笔记里，点运行就地展开。数据是同页 Database 的同一份，笔记上下文最完整。
适合 记录型场景（发货日志、读书笔记里的小工具） · 代价 宽度只有一栏，复杂应用挤
方向 B · 借自 Database 页
应用页面
应用本身就是一页，进收藏、分享、回收站全是现成语义。打开是整页画布，控件顶头一列，最不发明。
适合 独立使用为主、偶尔引用 · 代价 和笔记的"边写边用"弱一点
方向 C · 借自 Muse Spaces
侧栏启动器 + 工作台
侧栏单列一个「小应用」区，工作台把所有应用摆成活磁贴。固定入口最强，但把应用从"页"拉成了"工作台的一部分"。
适合 常用工具集、仪表盘型 · 代价 与页面树/分享的统一性要额外对齐

怎么比：A 和 B 不是二选一——同一页在笔记里显示就是 A，单独打开就是 B，UC-15 的方向本来就是"页面 + 就地显示"。C 是另一个范式：应用不进页面树，进自己的启动器。三个原型演示数据互相独立，刷新即复原。

原型只做壳与交互，无真实持久化、无沙箱；应用图标为占位 emoji。
