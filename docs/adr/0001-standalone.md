# ADR-001：独立单体服务拥有内容与权限

状态：已实施。附件存储与数据副本已由 [ADR-003](0003-attachment-files.md) 更新。

## 问题

原项目依赖缺失的 Terminus SDK 和宿主平台。源码已有编辑器、分享界面和历史投影，但没有独立身份、持久化或部署入口。

## 调用方

用户执行 `npm start` 后从浏览器登录。编辑器提交一批记录变更。服务端验证每个空间和记录，然后原子提交。Agent 使用 `/api/v1/pages`，不需要打开浏览器。

```ts
await request("/api/records/batch", {
  method: "POST",
  body: JSON.stringify({ requestId, writes }),
});
```

## 两种结构

方案 A：React 编辑器、同源 HTTP 服务和 SQLite。服务端拥有记录和权限。浏览器仅拥有远端记录的投影与待保存覆盖。字段级旧值检测处理并发冲突。

方案 B：Yjs 文档拥有正文。WebSocket 同步文档更新。关系数据库保存账号、目录和权限。浏览器把现有编辑动作映射为 CRDT 事务。Agent 也必须修改同一份 CRDT。

选择 A。它保留现有记录模型和编辑动作，能直接构成本地及容器部署。B 更适合字符级实时共编，但需要重新适配富文本、撤权更新、版本恢复及块树。

## 形状

`schema.ts` 是记录字段的类型和验证来源。`src/platform/schema.ts` 提供本地声明构建器，不再引用外部 SDK。`LiveCollection` 负责本窗口乐观覆盖、轮询和重试。`Plane` 与现有 `WorkspaceDocument` 保留调用契约。

同一事件中的记录写入在微任务中形成批次。批次可以跨个人与共享空间。服务器用一个 SQLite 事务处理整个批次。分享和停止分享不允许部分提交。停止分享同时撤销成员、待接受邀请和公开链接。

`Store` 拥有记录、空间继承、版本及持久化知识。HTTP 边界拥有认证、请求校验和协议响应。正文、历史及 Agent 不保存第二份内容真源。

## 红线检查

- 所有读写由服务端检查权限。
- 站点管理员不会自动获得私有页面。
- 正文与 Agent 使用同一套页面、块和版本。
- 公开文件必须被发布内容引用，并位于同一存储空间。
- 空间内每页必须属于可追溯的分享树。
- 服务端检查块和历史 ID 与所属页面一致。
- 批次请求 ID 保证响应丢失后的重试不重复执行。
- 轮询保留待写覆盖，并丢弃早于已确认写入的在途响应。
- 退出登录前等待保存，再整页重载，避免跨账号复用写队列。

## 接受的代价

接受单实例运行，换来单个可备份数据库和少量部署依赖。

接受约 1.5 秒的协作轮询，换来无需消息代理和 WebSocket 服务。接受同一字段冲突时明确拒绝，换来不静默覆盖内容。界面提供未保存草稿下载。

接受 Agent 的纯文本全文替换接口，换来清楚且可验证的首版协议。调用者需要保留富文本时，应省略 `text`。
