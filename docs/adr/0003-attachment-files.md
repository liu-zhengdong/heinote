# ADR-003：附件文件与数据库元数据分离

- 日期：2026-11-10。
- 状态：已采用。
- 关联：独立部署 UC-01、公开分享 UC-04、版本恢复 UC-05。

## 选择

图片、预览图和普通附件保存为数据目录内的不可变文件。SQLite 的 `files` 表只保存空间、逻辑路径、类型、大小和内容 SHA-256。

文件模块独占附件索引与物理文件的读写。服务器先检查权限，再调用该模块。物理文件名由内容哈希产生。客户端逻辑路径不参与磁盘路径拼接。

浏览器继续使用现有上传与读取接口。私有附件需要会话和空间权限。公开附件继续验证分享有效性、页面实际引用与附件所属空间。Yjs 共编二进制继续与正文投影在 SQLite 事务内提交。

## 提交与副本

新附件先写临时文件。服务完成文件落盘与重命名后，再提交数据库索引。同一逻辑路径只接受相同字节的重复上传。替换附件使用新逻辑路径。

本轮不物理删除附件。数据副本先通过 SQLite 在线备份生成数据库快照，再复制附件目录。文件不可变且不会被删除，因此该顺序包含数据库快照引用的附件。并发上传可能让副本包含额外文件。临时文件不进入副本。

副本是包含 `notes.sqlite` 和 `attachments/` 的完整数据目录。恢复时停止服务，把副本复制到新的空数据目录，再以该目录启动。

## 备选与代价

独立对象存储服务增加进程、凭据及部署边界。当前单实例无需这些能力，因此使用文件系统。

接受同步短文件写入，沿用现有同步 SQLite 服务模型。文件读取使用流。接受未引用附件暂时占用磁盘，保留页面历史及数据副本的完整引用。附件清理和多实例存储另行设计。

## 部署范围

本轮仅支持全新部署。不提供旧附件 BLOB 迁移，不保留旧格式兼容读取。附件继续使用已有持久卷，无需外部对象存储服务。
